A tarefa.projetoId não possui notNull e unique pois em outas etapas do desenvolvimentos algumas terefas foram criadas antes da existencia de projetos, o que acarretaria em um problema caso fosse obrigatório inserir um projeto_id em todas as tarefas, já no segundo caso, realmente é inviável deixar um detalhe sem um projeto_id, não faz sentido. O unique não faz sentido pois um projeto pode ter mais de uma tarefa, utilizar o unique quebra o 1:n nesse caso, diferente da relação projeto-descricao onde um projeto só pode ter uma descrição e uma descrição só pode ter um projeto.

CREATE TABLE detalhes_projeto (
  id SERIAL PRIMARY KEY,
  projeto_id INTEGER UNIQUE NOT NULL REFERENCES projetos (id),
  descricao_longa TEXT,
  observacoes TEXT,
  prazo_final DATE
);

export const detalhesProjeto = pgTable('detalhes_projeto', {
  id: serial('id').primaryKey(),
  projetoId: integer('projeto_id').notNull().unique().references(() => projetos.id),
  descricaoLonga: text('descricao_longa'),
  observacoes: text('observacoes'),
  prazoFinal: date('prazo_final'),
})

IDSERIAL PK - id: serial('id').primaryKey() - Chave primária, identificador de um detalhamento.

projeto_id INTEGER UNIQUE NOT NULL - projetoId: integer('projeto_id').notNull().unique().references(() => projetos.id) - Coluna obrigatória, única, com chave estrangeira do projeto id.

descricao_longa TEXT - descricaoLonga: text('descricao_longa') - Coluna tipo texto para a descrição propriamente dita.

observacoes TEXT - observacoes: text('observacoes') - Coluna para observação.

prazo_final DATE - prazoFinal: date('prazo_final') - Coluna para a data de entrega, formatada com tipo date (sem hora).

obs: as ultimas 3 podem ser NULL.
